繁忙時間出現 --:-- (No Info) 且兩邊時間混亂，根本原因是原程式碼每 15 秒都在下載全香港數萬個站點的 API 資料庫，觸發了 KMB API 的請求頻率限制（Rate Limit）導致連線 Timeout，加上沒有加入去回程方向（dir / bound）過濾，使循環線（如 23M、26M）與雙向路線抓到同一班車的時間。 問題修復邏輯 * 精準路線 API：改為直接請求單一路線 API (/v1/transport/kmb/route-eta/{route}/1)，不再載入全港站點資料庫，徹底解決 Timeout 與斷線問題。 * 鎖定方向（dir / bound）：明確區分南行（去程 O / 往觀塘尖沙咀）與北行（回程 I / 往順利彩虹），避免 23M/26M 雙向時間互相覆蓋。 * 預設站點過濾：和樂邨南行協和街站點與北行站點分別獨立過濾，確保資料精準呈現。 以下是完整修復後的 HTML / JavaScript 程式碼，複製並替換即可正常運作： KTMC Wo Lok Estate Bus Estimated Arrival Time Display System
